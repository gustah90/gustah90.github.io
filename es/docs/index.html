Documentación del portal

Arquitectura, calidad y observabilidad de este proyecto.

Arquitectura e idiomas

Astro genera páginas estáticas en portugués, inglés y español. React puede añadirse para las interacciones. Java se integrará cuando tenga una función definida.

Publicaciones con CMS

Sveltia CMS funciona en un editor privado separado. Los borradores y las traducciones pasan por PR, versión, changelog y CI antes de integrarse. Los borradores y fechas futuras no aparecen en el portal. Una GitHub Release no despliega el sitio; la publicación pública sigue desactivada.

Criterios de calidad

Tipos, lint, pruebas unitarias, cobertura, Playwright con axe y Lighthouse CI forman parte del pipeline. SonarQube utiliza un servidor efímero en CI o un servicio persistente configurado. La evaluación manual WCAG sigue siendo obligatoria.

Objetivos del pipeline

  • Lighthouse: rendimiento ≥ 95; accesibilidad, buenas prácticas y SEO = 100 en las páginas auditadas.
  • Playwright: teclado, idiomas, versión, reflow y ausencia de infracciones axe A/AA.
  • Cobertura por archivo de componentes y lógica ejecutable: ≥ 80% en líneas, instrucciones, funciones y branches.
  • SonarQube: Quality Gate aprobado tras configurar el servicio; las plantillas Astro también se verifican con lint, tipos y pruebas de navegador.

Instrumentación local

Por defecto, los eventos y Web Vitals permanecen en memoria en esta página. No usamos cookies ni almacenamiento persistente ni enviamos telemetría automáticamente. El botón inferior permite enviar un diagnóstico al colector opcional. No se recopilan argumentos de URL, mensajes de error, stacks ni datos de identificación.

LCP, CLS e INP aparecen cuando el navegador proporciona la medición. Una métrica ausente no significa cero. Los registros se reinician con cada navegación.

Publicación y versión

package.json define la versión, CHANGELOG.md registra los cambios y el Dockerfile expone APP_VERSION y VCS_REF. El build presenta la versión en el pie y en /version.json. La publicación requiere todos los checks y la revisión final.
