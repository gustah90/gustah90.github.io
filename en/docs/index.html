Portal documentation

Learn how this site is built, how articles are published, and what is checked before each new release.

Architecture and languages

The site is built with Astro, which generates the pages before they are published. English, Portuguese, and Spanish each have their own URLs. Small TypeScript modules handle features such as search, theme switching, and loading more articles.

Posting with the CMS

Articles are written in a private Sveltia CMS editor. Each change goes through a pull request, receives a version, and is recorded in the changelog. Once the automated checks pass, deployment runs as a separate step. Drafts, future-dated posts, and translations awaiting approval stay out of the public site.

Quality criteria

Before a change is merged, the pipeline checks formatting, types, and code behavior. Browser tests cover the main navigation flows, while axe and Lighthouse help identify accessibility and performance issues. SonarQube also checks code quality. Manual review complements these checks, particularly for accessibility.

Pipeline targets

  • Lighthouse: performance ≥ 95; accessibility, best practices, and SEO = 100 on audited pages.
  • Playwright: keyboard navigation, languages, version, reflow, and no axe A/AA violations.
  • Per-file executable logic and component coverage: ≥ 80% for lines, statements, functions, and branches.
  • SonarQube: a passing Quality Gate on the temporary CI server or configured service; Astro templates are also checked through lint, types, and browser tests.

Local instrumentation

This page shows a limited diagnostic view of your current visit. Events and performance measurements stay in browser memory; telemetry is neither sent automatically nor stored persistently. GitHub Pages does not run the optional collector, so diagnostic submission is disabled here. URL parameters, detailed error information, and identifying data are excluded from these records. Your theme choice is saved on your device. Comments load automatically. If you authorize sign-in, Giscus may also save its own session. Comments are public on GitHub.

LCP, CLS, and INP appear when the browser can measure them. If a metric is not yet available, its value should not be treated as zero. The records reset when you open another page.

Publishing and version

Every release has an identifiable version and a changelog. The version comes from package.json, and the Dockerfile exposes both the version and the code revision so the build can be traced to its source. You can find these details in the footer or at /version.json. Deployment proceeds only after the checks for that revision pass.
